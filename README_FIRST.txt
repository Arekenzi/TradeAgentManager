TRADE AGENT MANAGER — FIREBASE v25.0.1 STABLE

ЧТО ИСПРАВЛЕНО В ЭТОЙ СБОРКЕ
- Firestore — единый источник общих данных; Cloudflare Worker больше не участвует в заказах, входе, остатках, пользователях и синхронизации.
- Realtime: заявки, удаление заявок, оплаты/возвраты, остатки, настройки, пользователи, контрагенты, общий резерв товара и фотографии приходят автоматически через Firestore listeners.
- Удаление заявки администратором отправляется в Firestore сразу; у менеджера она исчезает автоматически. 10-секундная «Отмена» восстанавливает заявку обратно.
- Исправлена идентификация пользователей: каждый Firebase-пользователь имеет свой appId (admin / bazarbay / kusherbay / alieva), роли и права больше не смешиваются.
- Исправлен logout и смена пароля — используются Firebase Authentication, а не старый Worker.
- Убран старый скрытый дубль панели заказа с двумя «+». Остается одна панель: контрагент / новый контрагент / добавить товар / еще.
- Автообновление версии и циклическая перезагрузка отключены. Проверка версии запускается только вручную из профиля.
- Фото больше не требуют Firebase Storage/Blaze. Они хранятся в Firestore по одному документу на SKU, уменьшены перед загрузкой и НЕ сохраняются base64 в localStorage телефона.
- Старые фото вида @kv: временно читаются со старого photo-endpoint и администратор автоматически пытается перенести их в Firestore. После успешного переноса для этих фото Cloudflare больше не нужен.
- Общий доступный остаток учитывает заказы ВСЕХ менеджеров через коллекцию usage, при этом менеджер не получает чужие заявки.
- GitHub Pages paths исправлены: manifest, иконки и PWA работают из /TradeAgentManager/, а не только из корня домена.

ПЕРЕД ПУБЛИКАЦИЕЙ
1. Firebase -> Firestore Database -> Rules: полностью замените правила содержимым FIRESTORE_RULES.txt и нажмите Publish.
2. Firebase -> Authentication -> Sign-in method: Email/Password должен быть Enabled.
3. Firebase -> Authentication -> Settings -> Authorized domains: добавьте arekenzi.github.io.
4. Firebase Storage НЕ включайте и Blaze НЕ нужен.
5. Загрузите содержимое этой папки в корень GitHub-репозитория TradeAgentManager.
6. GitHub -> Settings -> Pages -> Deploy from a branch -> main / (root).
7. Когда Pages даст адрес сайта, первым войдите ВАШИМ уже созданным Firebase email/password. Первый профиль фиксируется как admin в state/bootstrap. Не распространяйте ссылку до первого админ-входа.
8. После админ-входа: Меню -> Пользователи. Для bazarbay / kusherbay / alieva создайте отдельные email + временные пароли прямо из TradeAgent.

ПЕРЕНОС СТАРЫХ ДАННЫХ
- Новый домен GitHub Pages не видит localStorage старого домена.
- В старом TradeAgent: Настройки -> Скачать копию в файл.
- В новой версии под администратором: Настройки -> Загрузить из файла.
- Импорт заменяет общие заказы/остатки/настройки/контрагентов фотографиями из копии и сохраняет Firebase-пользователей.
- Если в копии фото представлены @kv:, приложение после входа администратора автоматически переносит доступные старые фото в Firestore в фоне. Не закрывайте приложение сразу после импорта больших объемов фото.

ВАЖНО ПРО WHATSAPP
- На iPhone/Android, если браузер поддерживает Web Share с файлами, TradeAgent передает PDF через системное «Поделиться».
- Обычный сайт не может без WhatsApp Business API сам вложить PDF в заранее выбранный чат. Поэтому fallback сохраняет PDF и открывает чат номера оператора.

ПРОВЕРКА ПОСЛЕ ПУБЛИКАЦИИ
A. Откройте админ на компьютере и менеджера на телефоне одновременно.
B. Менеджер создает тестовую заявку -> она появляется у администратора без ручного обновления.
C. Администратор удаляет ее -> она исчезает у менеджера автоматически.
D. Загрузите одно фото товара на компьютере -> оно появляется на телефоне автоматически.
E. Измените остатки -> каталог на телефоне обновляется; общий резерв учитывает заявки разных менеджеров.
F. Перезагрузите сайт/ярлык несколько раз: сообщение «обновляю версию» не должно появляться само.
